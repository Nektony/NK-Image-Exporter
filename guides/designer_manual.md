# FigmaImageExporter — инструкция для дизайнера

Чтобы иконки из Figma автоматически попадали в наш проект через плагин, нужно соблюсти конвенцию. Один раз разложил — дальше каждый экспорт это одна кнопка.

> **Перед тем, как что-то размечать**, прочитай [`what_to_export.md`](what_to_export.md) — там описано, какие ассеты вообще выносим в плагин, а какие программисты рисуют сами или берут из системы. Этот документ — про *как разметить*; тот — про *что разметить*.

---

## 1. Куда класть иконки

Создай в файле отдельную страницу или фрейм — туда выноси **только** то, что должно попасть в код. Все варианты одного ассета (light, dark, hover, lock и т.д.) держи рядом друг с другом — удобно ревьюить и обновлять волной.

Пример раскладки:

```
Dev page
├── Preview
│   ├── img_exp/macbook-light
│   ├── img_exp/macbook-dark
│   ├── img_exp/macbook-lock-light
│   ├── img_exp/macbook-lock-dark
│   ├── img_exp/ai-state
│   ├── img_exp/ai-hover
│   └── img_exp/domians
└── test_dir
    └── img_exp/group-domains-test
```

---

## 2. Конвенция имён — главное

> **Префикс `img_exp/` — обязательный.** Без него плагин слой не возьмёт. Считай это меткой «эту картинку отдаём в проект».

> **По умолчанию слой считается светлой темой.** Никаких суффиксов писать не нужно.
> - `img_exp/icon` — это **светлая** версия (по умолчанию).
> - `img_exp/icon-light` — то же самое, явно помеченная светлая. Используется если хочешь подчеркнуть, что обязательно нужна тёмная пара.
> - `img_exp/icon-dark` — тёмная пара.

> **Парность light/dark:**
> - `img_exp/icon-light` **обязан** иметь рядом `img_exp/icon-dark` — иначе ошибка `Light layers without a dark counterpart`.
> - `img_exp/icon-dark` **обязан** иметь рядом либо `img_exp/icon`, либо `img_exp/icon-light` — иначе ошибка `Dark layers without a light counterpart`.
> - `img_exp/icon` (без суффикса) — `-dark` пара **необязательна**. Если её нет, плагин попытается подобрать тёмный вариант через цветовые переменные коллекции; если не получится — выгрузит только светлый.

> **Маркер плотности (опциональный):** между `img_exp/` и именем можно вставить `1x/` или `2x/` — для ассетов, которым нужна **только** одна плотность.
> - `img_exp/foo` — обе плотности (`@1x` + `@2x`), как обычно.
> - `img_exp/1x/foo` — только `@1x`. Без retina-пары.
> - `img_exp/2x/foo` — только `@2x`. Без `@1x`.
> - Маркер композируется с light/dark: `img_exp/1x/foo-dark`, `img_exp/2x/bar-light` и т.д. — всё валидно.
> - Light и dark должны иметь **одинаковую** плотность. `img_exp/foo-light` ↔ `img_exp/1x/foo-dark` — ошибка `Density mismatch in light/dark pair`.
> - Маркер не попадает ни в имя файла на диске, ни в Swift-кейс. `img_exp/foo` и `img_exp/1x/foo` дадут одинаковое имя ассета и сломают экспорт как `Duplicate image names` — выбери один формат для каждого ассета.

## 3. Что можно использовать в именах

- Латинские буквы (`A-Z`, `a-z`), цифры, `_`, `-`.
- Любые другие символы (пробелы, кириллица, точки, `/` кроме обязательной в префиксе) автоматически заменятся на `_` при экспорте.
- Регистр сохраняется в файлах. В Swift `snake_case` и `kebab-case` нормализуются в `lowerCamelCase` — например, `img_exp/macbook-lock` станет в коде `macbookLock`.
- **Не дублируй имена.** Два слоя, которые после нормализации дают одну строку (например, `icon` и `icon-light` — оба превращаются в `icon`), сломают экспорт с ошибкой `Duplicate image names`.

---

## 4. Иерархия фреймов

Любой фрейм / группа / Section, в котором лежит `img_exp/…`, становится подпапкой в `.xcassets`. Это удобно для разработчиков — структура в Figma ровно повторяется в проекте.

`Preview/img_exp/macbook` → `<набор>.xcassets/Preview/macbook.imageset/`

Имена фреймов тоже сохраняй в латинице — кириллица превратится в подчёркивания.

---

## 5. Поле «Set name» в плагине

При экспорте нужно ввести **Set Name** — короткое имя набора (например, `Common`, `App`, `Sidebar`).

- Только латинские буквы/цифры/`_`, начинается с буквы или `_`, без пробелов.
- Можно оставить пустым — тогда название набора возьмётся по умолчанию.
- В одном проекте могут жить несколько наборов параллельно (`Common` для общих иконок + отдельный набор для специфичных) — спроси разработчиков, какое имя ставить под твой набор.

---

## 5b. Несколько наборов из одной страницы (multi-set)

Если на одной странице нужно собрать **сразу несколько разных Set'ов** в одном экспорте — сделай это через специальные фреймы прямо на корне страницы:

```
img_exp/SetName:Common      ← всё внутри уезжает в Set "Common"
img_exp/SetName:Sidebar     ← всё внутри уезжает в Set "Sidebar"
```

Имя фрейма должно начинаться с `img_exp/SetName:`, потом — название Set'а (те же правила что для UI-поля: латинские буквы/цифры/`_`, начинается с буквы или `_`, не Swift-keyword).

**Важные правила:**

- Эти фреймы должны быть на **корне страницы**. Внутри другого фрейма / группы / Section такой setname-фрейм не работает (ошибка `Nested SetName frame`).
- На корне можно держать **либо только setname-фреймы, либо ни одного**. Если есть хоть один setname-фрейм + лежит обычный `img_exp/foo` рядом на корне — ошибка `Loose img_exp at root in multi-set mode`. Выбери один режим.
- Когда найдены setname-фреймы, поле **Set Name в плагине игнорируется** — имя берётся из фреймов.
- Два фрейма с одинаковым `<SetName>` — ошибка `Duplicate set name`.
- Содержимое каждого setname-фрейма — обычное: подпапки, `img_exp/`-слои, light/dark, density-маркеры, всё как в одном Set'е. Сам фрейм `img_exp/SetName:Common` **не** становится подпапкой в `.xcassets` — он играет роль «обёртки», а не папки.

В архиве будет несколько обёрточных папок бок о бок — `CommonFigmaImageAssets/`, `SidebarFigmaImageAssets/` и т.д. Разработчику просто распаковать каждую в нужное место.

---

## 6. Как запустить экспорт

1. Открой плагин **NK Image Exporter**.
2. Введи **Set Name** (например, `Common`).
3. Нажми **Export page (img_exp/)**.
4. Скачается файл `images.zip` — отдай его разработчикам.

---

## 7. Что плагин ловит как ошибку

Все ошибки выводятся в плагине с полным путём к проблемному слою — найти его быстро.

- **Light layers without a dark counterpart** — есть `img_exp/X-light`, но нет `img_exp/X-dark`.
- **Dark layers without a light counterpart** — есть `img_exp/X-dark`, но нет ни `img_exp/X`, ни `img_exp/X-light`.
- **Density mismatch in light/dark pair** — у light и dark разные density-маркеры (например, `img_exp/foo-light` и `img_exp/1x/foo-dark`). Поставь одинаковый.
- **Duplicate image names** — два слоя дают одинаковое имя после нормализации. Включает кейсы: `img_exp/icon` + `img_exp/icon-light` оба → `icon`; `img_exp/icon` + `img_exp/1x/icon` оба → `icon`; `img_exp/1x/icon` + `img_exp/2x/icon` оба → `icon`. Выбери один формат.
- **Image size validation failed** — `@2x` версия не ровно в 2 раза больше `@1x`, либо размер light не совпадает с размером dark. Чаще всего это значит, что слой подвинут на субпиксели — попробуй привязать к целым координатам.

**Ошибки multi-set режима** (когда на корне страницы есть `img_exp/SetName:…`-фреймы):

- **Loose img_exp at root in multi-set mode** — рядом с `img_exp/SetName:`-фреймом на корне валяется обычный `img_exp/foo`. Перенеси его в один из setname-фреймов (или убери все setname-фреймы, чтобы вернуться к single-set режиму).
- **Nested SetName frame** — `img_exp/SetName:`-фрейм лежит не на корне, а вложен в другой фрейм. Подними его на корень страницы.
- **Duplicate set name** — два фрейма с одинаковым `<SetName>` (например, `img_exp/SetName:Common` встречается дважды). Переименуй один.
- **Invalid set name** — в `img_exp/SetName:<X>` имя `<X>` не валидно как Swift-идентификатор (например, начинается с цифры, содержит пробел/дефис, или Swift reserved word). Поправь.

И отдельно — **не ошибка, а warning после успешного экспорта**:

- **«N images saved, but M required size correction»** — экспорт прошёл, ZIP скачался, но плагин у части картинок сам подправил `@2x` на 1 пиксель (дописал прозрачный край или обрезал). Под warning'ом будет список этих картинок с полным путём по иерархии слоёв и было→стало по размерам. Это значит, что у исходного слоя дробная ширина или высота (например, 24.5 × 24), и при рендере Figma по-разному округляет 1x и 2x. Авто-фикс сильно замедляет экспорт — поправь слой, чтобы координаты и размеры были целочисленными, и в следующий раз warning'а не будет. Эта плашка **не уходит сама** — нужно прочитать список и поправить.

---

## 8. Чего лучше не делать

- **Не меняй размер однажды экспортированной иконки** без согласования с разработчиками. Плагин запоминает размеры, и при следующем экспорте сборка проекта в Xcode упадёт с понятной ошибкой. Это страховка от случайной поездки вёрстки.
- **Не дублируй имена** — `img_exp/icon` + `img_exp/icon-light` нельзя одновременно.
- **Не пиши имена кириллицей** — в коде будет нечитаемая каша из подчёркиваний.
- **Не клади `img_exp/…` слой внутрь другого `img_exp/…`** — плагин не заходит внутрь помеченных узлов, вложенный потеряется.

---

Если что-то непонятно или плагин ругается странно — пиши, разберёмся. Текст ошибки всегда содержит полный путь к проблемному слою (страница → фрейм → … → имя слоя).
